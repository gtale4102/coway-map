# 코웨이 고객사 지도 앱 — 인수인계 스킬

사용자가 새 채팅창으로 이동을 준비하거나 인수인계 문서를 요청할 때 이 스킬을 사용한다.

## 수행 절차

1. **현재 대화의 작업 맥락 파악**
   - 이번 대화에서 완료된 작업 (버전, 기능, 버그픽스)
   - 미완료/보류 중인 항목
   - 중요한 결정 사항

2. **기존 인수인계 문서 확인**
   - 업로드된 파일 중 `인수인계_요약 (대화0N).md` 형식의 파일을 찾아 읽는다
   - 없으면 아래 기본 구조를 기준으로 작성

3. **새 인수인계 md 파일 생성**
   - 파일명: `인수인계_요약 (대화0N).md` (N은 이전 파일 번호 +1)
   - outputs 폴더에 저장
   - 이전 문서 내용 + 이번 대화 내용을 통합해서 작성

## 인수인계 문서 필수 포함 항목

### 1. 프로젝트 개요
- 앱 목적, 기술 스택, 파일 구조, 배포 방법, API 키

### 2. 버전 관리 규칙
- 현재 버전 명시
- 버전 체계 설명 (정수부=큰구조변화, 첫째자리=중간기능, 둘째자리=자잘한수정)

### 3. 데이터 구조 (★ 가장 중요)
- 현재 customer 객체 구조 전체
- v5.00 이후: contacts[] 없음, addresses[].contactName/contactPhone 사용
- "공용 담당자" 개념 없음 — 담당자는 주소 블록 안에만 존재
- 마이그레이션 함수 코드 포함

### 4. 이번 대화에서 변경된 내용
- 완료된 기능 (버전별)
- 핵심 코드 스니펫 (함수명, 동작 방식)
- 버그 수정 내역

### 5. 이전 대화에서 이어받은 주요 기능
- 현재 유효한 모든 기능 목록 (간략히)
- 상세 내용은 이전 인수인계 md 참고 안내

### 6. 작업 방식 주의사항
- GitHub 직접 접근 불가 → 파일 다운로드 후 직접 push
- bash 워크스페이스 다운 시 Read/Edit 파일 도구로 전환
- 확인 없이 작업 진행 금지
- 공간적/시각적 작업 시 직접 렌더링 후 확인

### 7. 보류/미결 항목
- 현재 보류 중인 모든 항목

### 8. 다음 작업 시 체크리스트
- 최신 index.html 버전 확인
- 데이터 구조 확인 (v5.00 이후 기준)
- 버전 번호 갱신 잊지 말 것

## 완료 후

파일을 저장하고 `mcp__cowork__present_files`로 사용자에게 전달한다.

새 채팅창에서 이 파일을 업로드하면 바로 작업을 이어갈 수 있다고 안내한다.
