## 1. 시도했다가 실패해서 버린 방법과 이유

### 1-1. 클러스터 버블 숫자를 "업체 개수"로 바꾸기 — 두 가지 방법 모두 실패
**시도 A**: 카카오 `MarkerClusterer`의 `texts` 콜백에서 직접 계산한 업체 수를 반환
- **실패 이유**: `texts` 콜백이 숫자(count) 하나만 인자로 받도록 설계되어 있고, 어떤 마커가 묶였는지(마커 목록)를 넘겨주지 않음. 그 안에서 "이 숫자에 해당하는 마커가 병합 핀인지"를 역으로 판단할 방법이 없음. API 설계상 불가.

**시도 B**: `clustered` 이벤트로 클러스터링이 끝난 뒤 버블 DOM 엘리먼트에 직접 접근해서 텍스트를 덮어쓰기
- **실패 이유**: 카카오 개발자포럼에 "클릭이 안 되는 버그"로 공식 미해결 상태. 지도의 핵심 동작(버블 눌러서 확대)이 깨지므로 실용상 사용 불가.

**최종 채택**: 병합 핀마다 1x1 투명 마커("유령 마커", `GHOST_MARKER_IMAGE`)를 (업체수-1)개 같은 위치에 추가해서, 클러스터러가 세는 마커 개수 자체를 업체 수와 일치시키는 우회 방법.

### 1-2. 엑셀 가져오기/쓰기를 SheetJS(무료판) 하나로 통일하기
- **시도**: 양식 다운로드(드롭다운 포함)를 SheetJS로 구현
- **실패 이유**: SheetJS 커뮤니티 에디션(`xlsx.full.min.js`)은 데이터 유효성 검사(드롭다운 생성) 기능을 공식 지원하지 않음. 비공식 편법은 있으나 버전이 바뀌면 깨지거나 파일 손상 위험.
- **결론**: 읽기는 SheetJS 유지(구버전 .xls 읽기, 비정형 파일 처리에 더 안정적), 쓰기(양식 생성)만 ExcelJS 추가하는 하이브리드 구조로 결정. 두 라이브러리는 서로 충돌하지 않음.

## 2. 반드시 지켜야 하는 제약·원칙

### 2-1. 데이터 구조 원칙 (v4.00~)
- **`address.id` 보존 필수**: 고객사 수정 화면에서 저장할 때, 주소 배열을 새로 만들면 기존 id가 사라지고 그 주소에 연결된 모든 로그/연락처(`addressId`)가 고아(orphan)가 됨. `addAddressRow()`가 폼에 추가되는 즉시 `dataset.addrId`로 id를 부여하고, 저장 시 그 값을 그대로 쓰는 구조를 절대 깨면 안 됨.
- **`addressId` 없음 = 공용으로 자동 처리**: 과거 데이터(addressId 없는 로그)와의 호환을 이 규칙 하나가 담당함. `belongsToAddrFilter()`가 이 규칙의 핵심. 수정하면 과거 데이터가 상세화면에서 사라짐.
- **삭제된 주소에 연결된 로그도 공용으로 자동 취급**: 같은 함수에서 "이 addressId를 가진 주소가 지금 address 배열에 존재하는지" 체크 후, 없으면 공용으로 취급. 이 로직을 제거하면 주소 삭제 시 해당 이력이 아무 화면에서도 안 보이게 됨 (데이터는 남아있지만 표시 안 됨).

### 2-2. 클러스터러 clear 시 유령 마커도 자동 정리
- `clusterer.clear()`가 호출되면 클러스터러에 등록된 유령 마커도 함께 지워짐. 유령 마커를 `markers` 객체에 넣지 않은 것도 이 때문. 만약 유령 마커를 `markers` 객체에 같이 넣으면 `setMap(null)` 호출이 중복되어 예외 발생 가능.

### 2-3. 병합 시 분류 자동 결정 금지
- 분류가 다른 두 고객사를 병합할 때, 어느 분류로 할지 자동으로 결정하는 로직을 넣으면 안 됨 (Claude 메모리 규칙 #25). 반드시 사용자가 선택. 다중 분류 동시 표기도 현재는 미구현·보류 상태.

### 2-4. `detailSelectedAddrId` 초기화 타이밍
- 상세화면을 닫을 때(`closeDetailSheet()`) `detailSelectedAddrId = null`로 반드시 초기화. 안 하면 다음 번에 다른 고객사 상세화면을 열었을 때 이전 주소 필터가 그대로 남아 엉뚱한 주소 탭이 선택된 채로 열림.

## 3. 설정 과정에서의 함정이나 실전 지식

### 3-1. `DEFAULT_CATEGORIES` 코드값 ≠ 실제 운영 분류
- 코드의 `DEFAULT_CATEGORIES`(최초 설치 시 시드값)는 `계약 중/잠재 고객/재계약 예정/휴면/대기업`이지만, **태일님이 실제로 쓰는 분류는 Google Sheets에 따로 저장된** `계약 중/친밀/보통/소원/발굴·가망/거점/미분류` 7개.
- 코드만 보면 DEFAULT_CATEGORIES가 현재 분류인 것처럼 보이는 함정이 있음. 분류 관련 작업 시 반드시 태일님에게 현재 분류명을 확인하거나, "양식 받기" 버튼으로 실시간 분류를 읽어오는 방식을 써야 함.
- "계약 중" 핀 색상을 `#4C88F5`로 바꾼 것도 **코드의 DEFAULT_CATEGORIES만 바뀐 것**이고, 기존에 저장된 실제 "계약 중" 분류는 자동으로 안 바뀜. 태일님이 분류 관리 화면에서 직접 색을 바꿔야 함.

### 3-2. 엑셀 날짜 셀 자동 변환 함정 (`cellDates: true`)
- 엑셀에서 날짜를 타이핑하면 엑셀이 자동으로 "날짜 형식 셀"로 변환하는 경우가 흔함. 이를 SheetJS로 읽으면 숫자(일련번호)로 읽혀서 날짜가 깨짐. `XLSX.read(..., { cellDates: true })` 옵션이 없으면 컨택날짜 컬럼이 전부 숫자로 들어와 이력 등록 실패. 이 옵션은 코드에 있지만 없으면 증상이 바로 안 나타나고(날짜 형식 셀이 없는 파일에서는 멀쩡하게 동작) 특정 파일에서만 발생하는 간헐적 버그처럼 보임 — 원인 추적이 어려움.

### 3-3. 카카오맵 `proj.pointFromCoords()` / `proj.coordsFromPoint()` 사용 타이밍
- `map.getProjection()`은 지도가 완전히 초기화된 뒤에만 유효한 값을 반환함. `renderAllMarkers()`에서 `const proj = map ? map.getProjection() : null`로 null 체크를 하고, 이후 proj 사용 전에 매번 `if (!isClusterZoom && showLabels && proj)` 조건을 다는 게 이 때문. proj가 null인데 `proj.pointFromCoords()`를 호출하면 바로 에러.

### 3-4. spiderfyPixels는 renderAllMarkers 안에서 `proj`를 먼저 구한 뒤 호출해야 함
- `spiderfyPixels(items, proj)`가 픽셀 기준으로 동작하려면 `map.getProjection()`이 필요함. 과거에는 `spiderfyAddrs(items.map(it => it.addr))`를 `proj`를 구하기 전(심지어 `const proj = ...` 선언 전)에 호출했음 — 지금은 순서가 맞지만, 리팩토링 시 spiderfy 호출을 proj 선언 앞으로 옮기면 undefined 에러 발생.

### 3-5. 라벨을 HTML 문자열이 아닌 DOM 엘리먼트로 만들어야 하는 이유
- 고객사명에 따옴표(`'`, `"`)나 특수문자가 들어가면 HTML 문자열로 `onclick="openDetail('${name}')"` 형태로 만들 경우 따옴표가 닫혀버려서 JS 에러 발생. `textContent`와 `addEventListener`를 쓰는 DOM 엘리먼트 방식으로 바꾼 이유가 바로 이것. HTML 문자열 방식으로 되돌리면 특수문자 포함 업체명에서 반드시 깨짐.

### 3-6. 클러스터링 중일 때 라벨/배지를 생략하는 이유
- `isClusterZoom`(줌 레벨 ≥ CLUSTER_MIN_LEVEL) 상태에서는 수백 개의 CustomOverlay를 생성하지 않도록 라벨/배지 렌더링을 생략함. 생략 안 하면 성능 저하(특히 모바일)와 시각적 혼잡이 동시에 발생. 이 조건을 제거하면 지도 전체 축소 시 화면이 눈에 띄게 느려질 수 있음.

### 3-7. 병합 팝업(`openMergeConfirm`)에서 라디오 버튼 쿼리 타이밍
- `document.querySelectorAll('input[name="merge-cat-choice"]')` 쿼리는 `confirmMergeCustomers()`가 호출되는 시점(팝업이 열린 상태)에 실행되므로 동작함. 팝업이 닫힌 후 이 쿼리를 실행하면 요소가 없어 선택값을 못 읽어 기본값(A의 분류)으로 처리됨. 팝업 닫기 → 병합 순서를 반드시 유지할 것.

### 3-8. openDetail 시그니처 — `keepSelection` 4번째 인자의 의미
- `openDetail(id, origin, addressId, keepSelection)`: `keepSelection = true`이면 `detailSelectedAddrId`를 새로 덮어쓰지 않음. 이게 필요한 이유는 `selectDetailAddress()`가 내부적으로 `openDetail(..., true)`를 호출해서 화면을 다시 그릴 때, 사용자가 방금 선택한 주소가 초기화되지 않도록 하기 위함. 이 인자 없이 `openDetail`을 재귀 호출하면 탭 선택이 매번 초기화됨.
