# 통합설계 참고 — 코드에 안 남는 판단·실패·제약 (대화03)

코드를 읽어도 알 수 없는 내용만 수록함. 코드로 확인 가능한 구현 내용은 제외.

---

## 1. 시도했다가 버린 방법과 이유

### 1-1. 담당자-주소 드롭다운 연결 방식 (채택 안 됨)
- **시도한 방법**: 담당자를 별도 섹션에서 한 번만 입력하고, 각 주소 블록에서 "담당자 선택" 드롭다운으로 연결하는 방식
- **버린 이유**: 태일님이 "첫 번째 방법(주소마다 직접 입력)이 낫겠다"고 선택. 드롭다운 방식은 담당자가 여러 주소를 관리할 때 중복 입력을 줄일 수 있지만, 구조가 복잡해지고 직관성이 낮다는 판단.
- **결론**: 주소 블록 안에 담당자 직접 입력 + "위와 동일한 담당자" 체크박스로 중복 입력 불편을 해소하는 방향으로 결정.

### 1-2. "전체 공용 담당자" 개념 (완전 폐기)
- **원래 구조**: contacts[]에 addressId 없는 항목 = 전체 공용 담당자, addressId 있는 항목 = 주소 전용 담당자
- **버린 이유**: 태일님이 "공용이라는 개념 자체를 내가 설정한 적이 없다"고 지적. 원래 의도는 담당자가 기준이고, 담당자가 다르면 애초에 다른 주소 블록 또는 다른 고객사로 분리하는 게 맞음.
- **결론**: contacts[] 배열 전면 폐기, 담당자를 주소 블록 안으로 완전 통합. 과거 공용 담당자 데이터는 마이그레이션으로 첫 번째 주소에 귀속.
- **주의**: 대화02 인수인계 md에 "공용 담당자" 개념 설명이 남아 있으나 현재는 무효. 혼동 주의.

### 1-3. 검색창 선택 시 상세화면 열기 (변경됨)
- **기존 동작**: 검색 결과에서 고객사 선택 → 상세화면(detail-sheet) 열림
- **바뀐 이유**: 태일님이 "검색해서 선택하면 지도에 핀으로 표기되게 해달라"고 요청. 검색의 주 목적이 위치 확인이지 상세정보 조회가 아님.
- **결론**: 선택 시 상세화면 없이 지도 핀 위치로만 이동. 상세화면은 핀 클릭으로 따로 열어야 함.

## 2. 반드시 지켜야 하는 제약·원칙

### 2-1. 데이터 설계 원칙 (코드에 명시 안 됨)
- **담당자가 기준**: 담당자가 다르면 → 다른 주소 블록. 주소도 다르고 담당자도 다르면 → 아예 다른 고객사로 분리.
- 이 원칙은 코드 어디에도 강제되지 않고 사용자 운영 규칙임. 새 AI가 구조를 보고 "공용 담당자도 지원할까?"라고 임의로 추가하면 안 됨.

### 2-2. 컨택유형 미상 시 기본값 채우지 말 것
- 엑셀 가져오기에서 컨택유형이 방문/전화/메시지 중 명확하지 않으면 건너뜀(대화02에서 확정된 원칙).
- 이유: 태일님이 "방문으로 임의 기록되면 혼동 온다"고 명시적으로 지적한 사항.

### 2-3. 작업 전 반드시 승인 받기
- "어때?"처럼 의견을 묻는 말에 바로 코드 작업 진행하면 안 됨.
- 대화02에서 Claude가 확인 없이 진행했다가 지적받은 사례 있음. 결과물은 마음에 들었지만 패턴 자체는 재발 금지.

### 2-4. 버전 번호 2자리 고정
- v5.0이 아니라 v5.00으로 표기. 소수점 둘째자리까지 항상 표기.

### 2-5. 분류 색상 즉시 적용 안 됨
- 컬러피커에서 색 바꿔도 "확인" 버튼 눌러야 적용됨 (즉시 적용 아님). 이 UX는 의도된 동작이므로 바꾸지 말 것.

## 3. 설정 과정의 함정·실전 지식

### 3-1. GitHub Pages 배포 Timeout — 코드 문제 아님
- 배포 중 Timeout이 반복되면 코드나 설정 오류가 아닐 수 있음.
- githubstatus.com에서 Pages 항목이 "Degraded Performance"이면 서버 문제. Re-run failed jobs으로 재시도하면 됨.
- 이번 대화03에서 실제로 발생했고 재시도로 해결됨.

### 3-2. Cowork bash 워크스페이스 다운
- bash가 "VM connection timeout"으로 응답 없을 때가 있음.
- 이 경우 Read/Edit 파일 도구로 직접 작업으로 전환. 파이썬 스크립트 실행이 필요한 작업(패키징 등)은 bash 복구 후 진행.
- 현재 handover-coway 스킬 패키징이 bash 다운으로 인해 .skill 파일 대신 SKILL.md 파일로만 전달됨. 다음 bash 가능 시 패키징 재시도 필요.

### 3-3. Grep 도구 한글 패턴 매칭 실패
- Grep 도구에 한글이 포함된 검색 패턴을 쓰면 매칭이 안 되는 경우 있음.
- 대안: bash grep 또는 python3으로 우회.

### 3-4. openAddSheet f-contacts 초기화 — 패턴 두 가지 존재
- 고객사 추가 폼 초기화 시 f-contacts 관련 DOM 초기화 패턴이 코드 내에 두 가지 형태로 존재할 수 있음.
- v5.00 구조 개편 시 첫 번째 패턴으로 Edit 시도했다가 불일치로 실패, 두 번째 패턴으로 재시도해서 해결한 사례 있음. 이 영역 수정 시 실제 코드에서 패턴 먼저 확인할 것.

### 3-5. GitHub 직접 연동 불가
- 현재 Claude Cowork에 GitHub MCP/커넥터 없음. 플러그인 추가 메뉴에서 검색해도 나오지 않음(이번 대화에서 직접 확인).
- 작업 흐름: Claude가 outputs에 파일 저장 → 태일님이 다운로드 → GitHub에 직접 push.

### 3-6. 스킬 파일 직접 쓰기 불가
- skills-plugin 경로(`...skills-plugin\...\skills\`)는 Cowork 파일 도구로 직접 쓰기 불가(outside connected folders 에러).
- 스킬 수정·신규 생성은 skill-creator를 통해 패키징(.skill 파일)한 뒤 설치하는 방식만 가능.
